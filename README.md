# Navier-Stokes Flow Past a Cylinder

Finite element solver for the incompressible Navier-Stokes equations in 2D and
3D, developed around the DFG/Schaefer-Turek flow-past-a-cylinder benchmark. The
code is written in C++ with deal.II and Trilinos, and supports MPI execution.

The solver uses Taylor-Hood finite elements, theta time integration, Oseen or
Picard linearization, optional Temam/grad-div/SUPG stabilization, and several
saddle-point preconditioners (`simple`, `block_triangular`, `yosida`, `pcd`).
Mesh generation is handled by Gmsh scripts; generated `.msh` files are local
artifacts and are ignored by git.

## Build

Load the required compiler/deal.II environment, then configure and build:

```bash
source /u/sw/etc/bash.bashrc
module load gcc-glibc dealii

mkdir -p build
cd build
cmake ..
make -j
```

The executable is generated as:

```bash
build/main
```

## Mesh generation

The `.prm` files expect the corresponding mesh files to exist locally under
`mesh/`. The mesh files are generated artifacts and are not intended to be
committed.

The mesh targets use the `gmsh` executable found in `PATH` by default. To use a
reproducible local Gmsh binary instead, download it with:

```bash
make gmsh
```

This installs Gmsh under `tools/`, which is ignored by git. The default version
is controlled by:

```bash
make gmsh GMSH_VERSION=4.15.0
```

Generate the 2D benchmark meshes `navierstokes_L0.msh` and
`navierstokes_L1.msh`:

```bash
make mesh-2d
```

Generate the 3D benchmark meshes `navierstokes3D_L0.msh` and
`navierstokes3D_L1.msh`:

```bash
make mesh-3d
```

Generate both 2D and 3D meshes:

```bash
make meshes
```

The following aliases are also supported:

```bash
make mesh 2D
make mesh 3D
```

To force the locally downloaded Gmsh binary:

```bash
make mesh-2d-local-gmsh
make mesh-3d-local-gmsh
make meshes-local-gmsh
```

For example, to generate only the level-0 3D mesh with local Gmsh:

```bash
make mesh-3d-local-gmsh MESH_LEVELS="0"
```

By default the mesh targets generate levels `0 1`. The levels can be changed
from the command line:

```bash
make mesh-2d MESH_LEVELS="0 1 2"
make mesh-3d MESH_LEVELS="0"
make meshes MESH_LEVELS="0 1 2 3"
```

The Gmsh output format is also configurable:

```bash
make mesh-2d MESH_LEVELS="2" MESH_2D_FORMAT=msh2
make mesh-3d MESH_LEVELS="0 1" MESH_3D_FORMAT=msh4
```

The relevant Make variables are:

- `MESH_LEVELS`: mesh refinement levels generated by the target. Default:
  `0 1`.
- `MESH_2D_FORMAT`: Gmsh format used for 2D meshes. Default: `msh4`.
- `MESH_3D_FORMAT`: Gmsh format used for 3D meshes. Default: `msh2`.
- `MESH_DIR`: output directory for generated meshes. Default: `mesh`.
- `GMSH`: Gmsh executable. Default: `gmsh`.
- `GMSH_VERSION`: local Gmsh version downloaded by `make gmsh`. Default:
  `4.15.0`.
- `TOOLS_DIR`: local tool directory. Default: `tools`.

The 2D script supports levels `0`, `1`, `2`, and `3`. The 3D script supports
the same level values, but levels `2` and `3` can become expensive quickly
because the number of tetrahedra grows much faster in 3D.

## Run

From the `build` directory:

```bash
mpirun -np 8 ./main ../flow_past_cylinder_2d.prm
```

For the 3D configuration:

```bash
mpirun -np 8 ./main ../flow_past_cylinder_3d.prm
```

Serial execution is also possible:

```bash
./main ../flow_past_cylinder_2d.prm
```

## Main parameters

The runtime configuration is controlled by the `.prm` files.

### Mesh and discretization

- `Mesh file`: mesh imported by deal.II.
- `Velocity degree`: polynomial degree for velocity.
- `Pressure degree`: polynomial degree for pressure.
- `Final time`: final simulation time.
- `Theta`: theta-method parameter.
- `Time step`: timestep size.

### Solver

- `Nonlinear method`: `oseen`, `none`, `picard`, or `picard_relaxed`.
- `Nonlinear iterations`: maximum Picard iterations per timestep.
- `Nonlinear tolerance`: stopping tolerance for the nonlinear iteration.
- `Picard relaxation`: relaxation factor for `picard_relaxed`.
- `Preconditioner`: `simple`, `block_triangular`, `yosida`, or `pcd`.
- `GMRES restart length`: restart size for the outer FGMRES solver.
- `Linear max iterations`: maximum outer linear iterations.
- `Linear relative tolerance`: relative tolerance for the linear system.
- `Linear absolute tolerance`: absolute tolerance for the linear system.

Each preconditioner also exposes dedicated inner iteration limits in the `.prm`
file, for example `SIMPLE velocity max iterations`, `PCD pressure max
iterations`, and `Yosida Schur max iterations`.

### Stabilization

- `Temam`: enables the Temam correction.
- `Grad-div`: enables grad-div stabilization.
- `Grad-div coefficient`: coefficient of the grad-div term.
- `SUPG`: enables SUPG stabilization.

### Physics

- `Viscosity`: kinematic viscosity.
- `Inlet velocity`: maximum or reference inlet velocity, depending on the
  selected inlet profile.
- `Inlet channel height`: channel height used in the parabolic inlet profile.
- `Inlet ramp time`: ramp time for time-dependent inlet profiles.
- `Outlet pressure`: imposed outlet pressure value.

## Algebraic system

At each linearized solve the code assembles a saddle-point system of the form

```text
[ F  -B^T ] [u] = [f]
[ B   0   ] [p]   [g]
```

where:

- `F` contains the velocity mass, diffusion, convection, and enabled
  stabilization contributions after Dirichlet constraints are applied;
- `B` is the discrete divergence block;
- `-B^T` is the stored pressure-gradient block;
- the pressure block is zero, with no artificial pressure regularization used
  in the benchmark configuration.

The pressure Schur complement is approximated differently by the available
preconditioners:

- SIMPLE uses a diagonal velocity approximation and an under-relaxed pressure
  correction.
- Block triangular uses a triangular factorization with an approximate Schur
  complement.
- Yosida uses a mass-based approximation of the velocity inverse inside the
  Schur complement.
- PCD uses pressure mass, pressure convection-diffusion, and pressure Laplacian
  operators to approximate the pressure Schur inverse.
